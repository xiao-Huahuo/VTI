# V58 安全暂停与机器监控（2026-09-30）

这是正式结果产生前的实现修订。用户要求随时停止并在右侧新建 V58 HTML 查看机器占用；正式模型调用仍为 0。原四题、12 个 block、24 sequence、分配、N/V 语义、主指标和 checkpoint 完整快照不变。

暂停按钮、`runner.py pause --batch-id <id>`、Ctrl-C 和 SIGTERM 都发出合作暂停请求。已开始的步骤继续完成、保存原始响应并提交 checkpoint，随后退出（状态 PAUSED、退出码 75）。此时不再开始新步骤或 sequence。暂停会等待当前模型请求与写盘，可能需要数分钟，不能保证立即释放模型内存。直接强杀、断电或模型服务崩溃仍按原规则：若 dispatch 后未有完整提交则不确定、禁止自动重发。

恢复时使用原 full/resume 命令和完全相同预算，增加 `--resume-paused`。暂停请求会移入控制历史，不删除原始收据；full 先回读已有安全 checkpoint，再恢复原未完成 sequence，完成的 sequence 不重跑。任何未提交操作、配置或预算身份漂移继续拒绝恢复。新增 `control/` 仅存控制事件及可替换的 UI 状态；科学事实仍在不可覆盖的 raw/checkpoints。

新页面为 `http://127.0.0.1:8773`，服务入口 `solutions/v58/src/progress_server.py`。页每 3 秒更新；机器采样约每 5 秒更新 CPU、GPU、统一内存可用比例、swap、磁盘、模型 CPU/GPU 分配、推理进程 CPU/RSS。macOS GPU 内存是驱动报告的共享内存估计，系统可用比例来自 memory_pressure；模型分配、GPU 内存与 RSS 相互重叠，不能相加。缺失指标显示不可用。页面只计正式 controller，开发 profiling 不计入正式分母。

服务只监听本机 127.0.0.1；页面暂停接口要求本次服务生成的控制 token，并拒绝异源请求。页面不启动模型或正式实验。当前没有正式批次，暂停按钮禁用。
